# Patamaps capability build plan

Updated 2026-10-14. **The active goal is a Rust-native implementation of MetaMap’s substantive capabilities and guarantees.** Reference: `@roryscot/metamap` 0.7.1, engine `399747a4ad05a37cd8db1cedd53048fad2175be4`.

The owner replaced exact JavaScript/API parity as the completion criterion. This plan supersedes the previous R0–R11/P0–P9 delivery gates. [The previous plan, README and conformance manifest](docs/history/capability-goal-transition-2026-10-14T15-22-48.455971Z/receipt.json) are byte-preserved history. The original 1,293-obligation ledger, reference tests, expectations, captures and failed runs remain evidence; they do not determine completion of this goal.

The README controls product scope, this plan controls implementation order and acceptance, and [SPEC.md](docs/SPEC.md) controls the current draft protocol. The [test classification and compatibility policy](docs/TEST_CLASSIFICATION.md) defines how reference evidence is used. A successful test, historical profile or implemented function alone does not establish current workflow acceptance.

## Implementation sequence

1. **M1 — Complete the native compiler workflow (C01–C09, C13–C14).** Reuse the existing compiler, checked derivations, uncertainty and risk engine. Run focused independent negative controls and the existing meaningful 40-case reference comparison. Capture success/rejection, verify replay, inspect/repair without publication, and build/run generated Rust code. Record exact source inventory, executor, commands and retained outputs. Fix an observed failure before expanding scope.
2. **M2 — Native policy extension and interface completion (C03, C11, C18).** Add only demonstrated missing functionality. The initial concrete gap is Rust-native custom constraints. Define registration identity, read-only context, bounded findings, failure/cancellation behavior, reserved built-ins and capture/replay limitations before implementing. Unknown evaluator, invalid findings or failure must never produce admission; structural/proof/security findings cannot be waived by a plugin. A native memory API is required only if needed to complete a substantive workflow, not to reproduce object aliases.
3. **M3 — Governed candidate workflow (C10–C12).** Refresh pure artifact/proposal/approval checks using independent signatures and adversarial controls. Make Linux acceptance retain test material, then run current debug and release host workflows on actual ARM64/x86_64 Linux. Verify permissions, stale base/current trust, concurrency, five crash phases, implementation move and fresh-approved rollback. Tests use isolated fixture trust; production trust/bootstrap/activation require owner approval.
4. **M4 — Installed consumers and integration (C07, C15–C19).** Package the exact candidate, independently install it, run Rust/Python/TypeScript workflows, both migrations, discovery and scientific conformance. Audit no MetaMap candidate import/dependency. Refresh protocol/format/signature interoperability only where a real integration requires it. Preserve original bytes and record conversion differences.
5. **M5 — Capability acceptance.** On one candidate, run the comprehensive native workflow, independent guarantees, installed-consumer and required-platform checks. Bind each matrix row to actual commands/outcomes/source identities; identify any residual format/semantic differences. Completion requires every substantive capability implemented and verified, or an explicit owner disposition. No agent can silently narrow scope. Registry publication and production activation remain separate actions.

Focused checks run while developing a capability. Comprehensive milestone checks run when the candidate crosses a complete workflow/package/platform boundary or new failures warrant them. The old all-exports/all-JS-observables suite may still be run for a demonstrated integration; it is not the daily build gate.

## Reuse, optimize and omit from the successor runtime

- **Reuse:** strict contracts/canonical vectors; graph identities, ownership/provenance and merge rules; relation vocabularies/laws; checked native compiler; uncertainty/risk engine; replay/proposals/governance/activator; existing scientific formats, licensed discovery adapters, native emitters and consumer fixtures.
- **Optimize after measurement:** shared proof/mapping closures, indexed graph/authority lookup, batched projection reuse, deterministic bounded cancellation and source-capture footprint. Retain raw benchmark trials. Rust alone does not establish a speed or memory advantage.
- **Omit runtime dependency:** MetaMap package, its TypeScript policy engines, Node/Ajv inside the Rust kernel, shell lock helpers, redundant semantic wrapper engines and ambient trust/time. Original sources remain preserved reference material. Optional language discovery can use its own compiler/tooling.
- **Do not build without a requirement:** a daemon/database/RPC framework, general n-ary inference beyond declared laws, arbitrary executable relation packs, a replacement frontend framework or literal JS exception/prototype machinery.

## Compatibility and evidence decisions

The native typed API is the primary API. Parsed JSON has no checked/admitted/authorized status. Private Rust constructors and borrowing preserve immutable input ownership; persisted records are rechecked. Pure computation uses explicit context/time, and the protected host repeats current authorization under its lock.

Preserve format, canonicalization, hashes and signed bytes wherever a demonstrated integration consumes them. Original MetaMap records keep their original version, digest and executor. A converted Patamaps draft record receives its own declared version/domain, complete migration report and fresh evaluation; conversion cannot upgrade provenance or reuse an old approval.

Exact exception wording, prototypes, JS object identity and incidental mutation are not default requirements under the owner’s revised goal. Existing compatibility code and tests remain in place. Removing code or local material is a separate change requiring the applicable approval; changing the goal does not authorize deletion.

Independent controls must catch a shared reference bug. Each reference comparison keeps complete inputs, expected decisions and both outputs, identifies normalization/differences before judging the result, and preserves failures. Test classification cannot rewrite expectations or silently remove a semantic/security/governance obligation. New proposed differences that affect a required guarantee stay open until resolved or owner-dispositioned.
