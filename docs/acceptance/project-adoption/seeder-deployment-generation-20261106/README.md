A staged owner launcher compared two genuine retained Seeder selections. It
rejected the older HTTP-only configuration generation before starting a server.
The matching WebSocket-configured generation passed the pinned Patamaps
`project-build-verify` command, then started its accepted Next output on the
declared loopback port. All seven public HTTP checks passed, including the two
exact compiled-asset digests and the three refusal responses.

The launcher borrowed the existing read-only runtime while three producer paths
were temporarily unavailable. An independent check rehashed 30 frozen inputs,
2,482 selected artifact files and 2,472 borrowed runtime files, checked 524
selected directories, and confirmed both selection pointers and all three
producer identities. The server and listener stopped. The 112 MB native
exclusive reservation charged 13,897,728 bytes of growth and released normally.
The unrelated database kept its identity and start time.

The first attempt expected a configured port that the original ephemeral-port
probe did not provide. It exited before Next startup and released its
reservation. The corrected harness exercised both cases with one declared port
and retained the first failure.

verifies the matching selection's bindings. This receipt covers the compiled
