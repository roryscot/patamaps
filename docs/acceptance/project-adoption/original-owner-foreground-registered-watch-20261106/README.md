# Foreground registered watch and active parent death on Norway

The original installed watcher ran with a staged policy runner bound to
the [reviewed retained capsule](../original-owner-registered-retained-capsule-20261106/README.md).
It queued the unchanged build and selection post-check separately through
the canonical scheduler. The no-op repeated zero application build
commands. The two native post-check calls produced one nonce-bound
verification for the existing selected pointer and input key. Three idle
observations found the watcher alive without a lease. SIGTERM returned
exit 130. Both reservations released automatically.

A separate case proved a registered native call was live before killing
only its test-owned parent. Independent review verified all eight
observed processes and seven groups stopped and the reservation released
automatically in 5.65 seconds against the 60-second bound. The cancelled
guard returned 75 and recorded a volume-query error during shutdown.
The watcher recorded cancellation and preserved the selected attempt.

The first foreground attempt refused before queueing because an accounting
import pointed at the wrong directory. The first active-parent attempt
queued behind a historical PID whose identity the scheduler could not
confirm. The PID belonged to the test's SSH connection at the time.
That queued request was cancelled before native work. The retry used a
detached test supervisor. Both earlier outcomes remain preserved.

Both reviews rehashed 2,482 selected files and 943 owner inputs and
verified the original selection and lock. The protected database matched
its prior identity. This qualifies the tested no-op and parent-death
paths through the staged runner. Changed-generation failure, race and
cancellation checks remain open.
