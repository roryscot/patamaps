# Five genuine staged native executor cases

Independent review accepts normal engine inspection, active cancellation, controller SIGKILL, guardian SIGKILL and active command-owner parent SIGKILL with a surviving trusted observer. Each isolated reservation finishes/releases automatically only after sealed source-bound ownership, stopped registered groups, clean private-channel/data-stream closure and unchanged bindings. Failed operations retain their nonzero results.

The parent watcher captures the actual kernel parent identity before admission and detects its loss while queued or active. The parent-death case preserves the original operation's exit75; the independent observer survives the controlled parent, obtains complete stopped proof and releases within 60 seconds. See review.json for actual timing, scope and digests. The observer's final exit code was not directly observed; its complete process-group stop was independently checked.

All 20 source inputs, 14 existing bridge controls, one runtime's 1,643 regular files/155 directories/nine links and ten private Mach-O objects, all system bindings, actual engine output and protected selected state were independently verified. The unrelated database retained its exact start identity. The canonical 1 GB job and all five private 512 MiB reservations released; original 4 GB/500 MB/100 GB machine limits remain.

A first shared-runtime setup failed with SIGXFSZ/EPIPE because a harness-log limit was inherited by the pinned archive extractor. No Patamaps inspection case launched in that attempt. The corrected harness observes log bounds separately; all original controller output/resource limits remain. Its failure and partial extraction remain on Norway. The earlier redundant-signal cancellation failure and manual recovery also remain.

These are five staged integration cases, with one qualified runtime reused. The proposed parent-watch diff and exact authored harness snapshots are included for review. The snapshots are tied to the original frozen Norway workspace and its private fixture; they are not a portable launcher or a source of activation authority.

Unsealed/surviving workloads, malformed/truncated/lost private channels including a zero-exit wrapper, changed bindings, ordinary fallback, atomic simultaneous acquisition and fair follow-up queuing still require completion of the full planned suite. Real owner watch failure/race/cancellation and other adoption gates remain separate. No installed guard, trust registry, policy, parallel activation or file deletion changed.
