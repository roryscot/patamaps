# Actual Next deployment refusal controls

Five scoped cases passed against the retained Linux-built Next16.1.6 standalone output: healthy public HTML before and after three negative cases; a non-server executable exiting 0 without readiness; a missing build-directory configuration refusing startup with exit 1; and the unchanged server serving HTML on 32140 while required 32139 remained closed. These are actual process/HTTP observations, rather than Dockerfile text or exit-code-only acceptance.

Staging verified all 2,480 original runtime files. Pinned Linux Node bytes and ELF64/x86_64 header, exact build-ID/receipt lineage, runtime file/link bindings and three configured host/source/compiler read denials were checked. Independent final verification confirmed original selected-pointer and staged-runtime bytes unchanged, all owned child processes stopped, both listeners closed and the owned container stopped/nonpaused/nonrestarting/PID0. Stopped-container inspection matched CPU 2, memory/swap total 1.5 GiB, PID 256, readonly root, network-none and only the registered fixed 512 MiB writable mount. Kernel limit values were not separately remeasured by this application driver; the installed executor's qualification covers enforcement.

The first results collector failed after executor exit 0 because it expected a redundant linuxBuildEstablished field absent from the new runtime receipt. Its failed receipt and diagnostic remain unchanged. A separate read-only verifier bound the saved controls to the exact successful Linux-build receipt, rechecked original file/link bindings, selection pointer and stopped container, and wrote a new successful verification receipt. The workload was not rerun and no frozen behavioral expectation was changed.

Wrong-architecture execution and stale generated-contract rejection remain open, as do authenticated backend/permission behavior, nonempty framework boundaries, latest-package adoption and practical edit/watch measurements. ELF header inspection is not wrong-architecture runtime refusal. This is not arbitrary Next/config support or release acceptance.

Only compact metadata and digests are public. Private application source, copied bootstrap variant, logs, full drivers and prior failure records remain under .tools/project-adoption/next-deployment-refusals-20261020 on Intel. No source patch or runtime image was published; no files, containers or images were deleted. Storage policy remains 4 GB growth / 100 GB retained / 500 MB reserve.
