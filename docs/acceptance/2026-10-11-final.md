# R0–R11 implementation acceptance

Date: 2026-10-11. **All R0–R11 gates pass for the declared draft profiles on
ARM64 macOS and Linux.** The implementation remains uncommitted and unpublished.
Production installation, key custody, trust bootstrap and consumer activation
have not occurred. The existing Git HEAD
`ab6efc333a3c90f7ce9235822b49098809d8b159` does not identify this implementation;
the package inventories identify its exact source bytes.

The nine Rust crates provide strict contracts, immutable indexed graphs,
scoped ownership, contextual and application-topology admission, checked laws
and proofs, typed uncertainty, unique risk closure, static native projections,
path trees, capture/replay, external approval verification, protected Linux
publication, bounded repair and offline inspection, workspaces and bounded
SSSOM/RO-Crate interoperability. Independently built routing and scientific
consumers execute static artifacts without the compiler at runtime. Python and
TypeScript SDKs invoke the same native evaluator.

## Governed lifecycle and Linux scope

The same [shared fixture](../../crates/bindloom-activator/tests/support/lifecycle.rs)
is used by portable and Linux tests. Two independently authored shards provide
canonical ownership and narrowing implementation delegation. A checked chain
derivation binds both premises; explicit policy tolerates unknown identity and
charges a complete three-mapping dependency closure once. Supported-only
identity and cost-two/zero-budget controls refuse.

The Linux sequence captures all three source files, replays, obtains an exact
external owner approval, activates through the fixed installed executable and
executes the generated native consumer under UID 65534. An implementation move
retains semantic IDs and receives a new current-base approval. Rollback receives
a fresh approval and the consumer executes again. CLI inspection and finite
repair leave the protected manifest unchanged; a viable repair remains an
unapplied proposal requiring approval. [Portable stages](lifecycle-pure.json)
provide separate proof/policy/replay/inspection/dispatch evidence.

The actual Linux guest used four CPUs, 6 GiB RAM, kernel `6.18.52-0-virt`, Debian
12 userland from the pinned official Rust image and a task-owned ext4 raw disk
with ordered data mode. It had no guest network device. Staged public/project
inputs were read-only; output export used a separate task-owned directory.
Docker was not restarted. [Runtime provenance](linux-vm/runtime-provenance.json)
records verified upstream checksums, image digests, bootstrap scripts and
preserved setup failures. The original vfkit checksum matched its published
asset, but signature validation failed; a task-owned ARM64 copy received only
an ad hoc virtualization entitlement. No global trust setting changed.

Real tests cover independent-UID permission denial, linked/foreign/malformed
objects, held-lock serialization and stale bases, current trust/revocation,
root-owner trust administration and all five SIGKILL phases: locked,
artifacts-ready, manifest-ready, precommit and committed. Accepted historical
state remains readable after revocation; retries and new changes recheck current
authorization. Errors after possible publication report indeterminate state.
This verifies process-crash behavior on the root-owned local ext4 profile.
Power-loss durability, other filesystem runtime behavior, root compromise,
malicious approved native code and production key custody are outside this
acceptance. macOS refuses protected activation.

## Reuse, optimization and limits

[The build plan](../../BUILD_PLAN.md) records source-level reuse decisions.
The successor reuses semantic IDs, authored correspondence/ownership/policies,
pinned negative fixtures, licensed scientific sources, consumer behavior and
optional discovery exporters. It rebuilds the evaluator, checked state model,
canonical contracts, native outputs and host transaction in Rust. Indexed graph
lookups and closure reuse replace repeated traversal; generated runtime code
does not carry the graph evaluator. The shell lock helper, reflective runtime
binding, ambient trust/time, broad waiver bypasses and probability claims from
scalar confidence are discarded.

D001–D009 remain explicit profile differences in
[the conformance manifest](../../fixtures/conformance.json), with independent
[D005/D006](reference-differences-final.json) and
[D007/D009](profile-differences.json) controls. All 53 reference suites have
declared native destinations; this does not establish full old API parity or a
one-for-one port of every old assertion. Unexplained drift is not relabeled as
compatibility. The strongest remaining objection to broader parity is that a
bounded shared corpus cannot prove agreement on untested inputs and profiles.

The scientific profile preserves seven licensed assertions, repeated pair
metadata, all five SKOS relations and uninterpreted confidence. Native lookup
and bounded RO-Crate regeneration/replay pass. Independent offline SSSOM-py
0.4.17/schema 1.0.0 and RDFLib 7.1.4 checks validate source/default/condensed
exports and the pinned RO-Crate context, 121 triples and 16 payload files.
The independent checker's known `strict=True` parser defect remains a recorded
failure. These checks establish the bounded format/profile, not scientific
truth or universal RO-Crate conformance. [Independent record](scientific-independent.json).

Native CLI JSON/escaped script-free HTML checks pass at the current engine.
Mouse/keyboard browser observations were on synthetic pages at historical
engine `58e035b0…`; renderer bytes remain unchanged. Later reconnect found no
available browser. No current-engine browser visit, screen-reader validation
or full WCAG certification is claimed. [Browser record](debugger-browser.json).

[Phase measurements](benchmarks/METHOD.md) retain seven trials, closed input
inventories, per-child peak RSS and artifact/binary/dependency footprints.
They cover valid/rejecting 1k/10k routing, 64-level delegation, eight branching
proofs, 32 projection specifications, topology removal and finite repair.
The 100k raw inputs exceed the 16 MiB bound and measure controlled refusal.
Optional Zod discovery is measured separately. There is no matched TypeScript
timing baseline, Rust speed/memory advantage, per-phase memory attribution,
Linux throughput claim or tail-latency guarantee.

Process discovery uses explicit bounded invocations and revalidation, with
caching disabled because arbitrary providers cannot prove a complete dependency
closure. Portable cached shards are untrusted and rechecked. Source receipts
and consumer build helpers are not OS sandboxes. Broader scientific imports,
new platforms and production adoption require their own controls; the completed
draft goal does not claim those expansions.
