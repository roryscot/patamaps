# Owned tool groups and invoking-parent death

The CLI configures its own hidden, versioned tool-supervisor entry. Each configured provider and each native Cargo/rustc invocation runs under a separate private helper group. The actual tool inherits that helper's group. A helper validates its actual parent PID and its own group ownership before executing a tool, then watches parent death independently of pipe-reader joins. Losing the invoking parent, including through SIGKILL, stops that helper's ordinary group. Nested Cargo helpers observe the provider's death in the same way.

The prior source implementation created separate provider/tool process groups without an invoking-parent watch. This is a source-inspection risk until a liveness probe observes the actual behavior. The preserved pre-guard Intel compiler and its queued probe remain separate from the new implementation. Acceptance requires actual parent SIGKILL, observed descendant PIDs and a check before any fixture cleanup; manually stopping a leaked process cannot turn the result into a pass.

Existing public process requests retain their 16 MiB bound, stdout/stderr bounds, cleared environment and deadline. The private header has a 16 MiB cap and the private transport has a 32 MiB cap for header plus the already bounded request. The helper transports the existing refusal classes through private exit codes. Failed helper calls return before waiting on pipe holders; the invoking process stops the whole owned helper group. An independent parent watcher also covers blocked pipe joins and input/output handling.

This is ordinary Unix process cleanup for trusted configured tools. It is not an OS sandbox for a provider that deliberately escapes its group. Linux and macOS are the declared process platforms. Library embedders must explicitly configure a compatible supervisor executable to obtain this parent-death behavior; unconfigured direct library execution retains its earlier bounded behavior. The CLI always configures its own executable. No VM, daemon, storage-policy change or additional runtime package is introduced.

The workspace executor identity includes the supervisor source. The isolated Linux source job runs actual provider and nested Cargo parent-death controls after the full source matrix, retaining process ancestry, timing, logs and every fixture. A passing source matrix alone is not evidence that these new liveness controls passed. The development selection driver, image/browser acceptance and MetaMap interoperability remain separate work.
