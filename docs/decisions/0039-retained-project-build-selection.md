# Retained project build selection

The native project-build PLAN --source OWNER --state STATE workflow combines the existing ProjectProfile capture, checked WorkspaceConfig and ProjectCommand contracts. Its explicit plan profile is patamaps-project-build-1, with project, workspace, buildSteps, verificationSteps and outputs. At least one build and verification command and one declared file/tree output are required.

State must be outside the source tree and any enclosing Cargo workspace; isolation is checked before state creation. Each attempt retains source capture, source staging, viable workspace baseline, fresh candidate, command reports and artifact snapshots. Generated workspace output paths must not collide with selected source paths. Both build and verification stages use the existing native command supervisor and captured-only nonsecret environment.

Artifact bytes, Unix mode bits and tree membership are fingerprinted after build steps and must remain unchanged through verification and final selection. Symlinks/special files in declared artifacts refuse. Source and all configured command/provider executables are rechecked before publication. A cooperative file lock excludes another driver; ordinary command failures, detected races and pre-publication interruption leave the old selection untouched. Failed/partial attempts remain. Atomic selection replacement retains the exact previous pointer in the new attempt before replacement. Events after replacement can report uncertain durability; a completed verified candidate is retained.

An unchanged key requires checking saved selection bindings and current artifact/input bytes, then reports verification:not-repeated and cacheHits:0. It does not claim commands ran again or prove complete external dependency closure. project-build-verify checks retained composition/capture/command/selected-artifact bindings without original source rediscovery or tool execution. Records are local development evidence, not signed execution attestations or current authorization.

This profile inherits bounded selected UTF-8 input capture and does not establish a complete build context, metadata restoration, opaque source dependency restoration, arbitrary tool sandboxing or runtime semantics. Runtime/readiness meaning belongs to explicit owner verification commands and still requires qualification. Foreground watch, actual project performance, installed consumers and full existing application qualification remain open. Application/storage guards continue to apply; this workflow does not override them.

Acceptance: coherent selection/no-op, missing or rejected admission, failing build/verification, source/tool/artifact mutation, exact tree/permission tampering, concurrent driver refusal, source/tool-unavailable binding verification, and interruption before publication with ordinary child cleanup.
