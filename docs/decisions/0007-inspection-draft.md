# Finite repair and offline inspection

R8 adds a read-only repair search and one shared explanation report for JSON and static HTML. Neither API can write sources, choose an active state root, sign, or activate. The repair vocabulary is explicitly supplied restore-mapping, select-target, remove-duplicate, and supply-declaration operations. Indices and digests identify exact captured mapping occurrences, including invalid duplicates. The retained duplicate cannot change in the same subset. A declaration cannot replace an effective declaration or introduce applicability; repair cannot create inferred proofs, evidence, grants, authority, waivers, budgets, or law changes.

The request binds one current-executor capture and one consumer projection. Multiple projection repair requests are outside Draft 1. Supplied edits are normalized in UTF-16 identity order; enumeration visits nonempty subsets in increasing cardinality and lexicographic order. Ranking uses edited records, declared ordinal cost, then proposal digest. Cost is not evidence or probability. Allowed/protected fact scopes are proposal boundaries, not external grants. Conservative action requirements are shown; the exact governed proposal must recompute all actions against the actual protected baseline before approval. A bad duplicate baseline can make comparison unavailable while its repaired candidate remains useful.

Limits are 32 edits, 4,096 recorded candidates, 60 seconds, 20 million cooperative work units and the existing 16 MiB wire/output bounds. Counts distinguish examined, recorded, unrecorded, unexamined and excluded combinations. Candidate, edit, work, elapsed, cancellation and output limits retain incomplete status. Minimality applies only to a completely recorded/explored finite supplied space; no global optimality is claimed. The cancellation token is host-only runtime state. Polls occur during graph indexing, cycle traversal, policy coverage and search, with checks around remaining bounded synchronous replay/JSON/projection stages; those stages can overrun a cooperative deadline. Cancellation is not captured as deterministic semantics.

Inspection verifies capture replay before deriving the report. It retains known/missing/ambiguous occurrences, declared ownership without authentication, exact source receipts without invented record membership, available generation/proofs/uncertainty/risk, rejected results, actual comparison differences, and declared impact paths. Issue subjects are separately classified by relevance. A truncated view says so. The HTML renderer takes only the immutable checked report; it escapes every candidate string, loads no external resources or scripts, uses native details/anchors/focus states, and exposes the same JSON report. Historical approval and active state are explicitly unevaluated.
