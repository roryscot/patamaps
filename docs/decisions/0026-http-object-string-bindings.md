# Checked HTTP object/string bindings

Scope: the cross-stack fixture's explicit POST operations, with an owned method/path, module map, Rust signature, status/error contract and JSON-schema request/response. A successful checked projection is required. The existing compose/admit/link, Rust and TypeScript projection machinery remains authoritative; this adds two source emission formats to link, http-rust and http-typescript.

The supported JSON Schema dialect is 2020-12. Each boundary must be an exact object with one to 64 properties, every property required, additionalProperties=false, and string fields with optional nonnegative minLength/maxLength. String length uses Unicode code points, within the Unicode scalar subset shared by Rust and JSON consumers. Unknown keywords, optional fields, references, composition, patterns, formats and non-string fields refuse. This is a bounded profile, not a general JSON Schema implementation. The [JSON Schema validation specification](https://github.com/json-schema-org/json-schema-spec/blob/main/specs/jsonschema-validation.md) defines the length contract.

Owner-authored graph attributes carry the schemas and literal frontend/backend endpoints. The handler has a unique digest-bound rust:crate::module::function locator and an explicit contained module path. The consumer stages and checks those exact file bytes; generated Rust declares that module and resolves the real export, request/response types and complete error variants through Cargo. Syntax/name equality does not establish a handler's meaning. No macro expansion or arbitrary Serde wire behavior is inferred.

The normal service router calls the generated dispatch, and Next.js uses the generated operation table/client. Both sides validate serialized bodies. The client rejects undeclared statuses, malformed success bodies and unexpected error contracts. Runtime consumers import only generated source and application dependencies. They do not invoke a graph compiler on request paths.

Acceptance requires actual Cargo and Next.js compilation, independently frozen HTTP results and refusal controls: moved file with stable operation ID, absent export, wrong signature, duplicate operation/binding, method/path change, request/response shape change, Serde field removal, missing router registration and disabled handler feature. An unrelated Rust file edit changes source evidence without changing owned semantic operation identity. Fresh candidate directories retain failures and leave prior candidates usable; coherent selected-candidate publication is a separate M5 obligation.

The [M2 scoped receipt](../acceptance/cross-stack/m2-http-bindings/receipt.json) records 20 passing independent controls, actual Cargo/Next/HTTP behavior and full native workspace regression gates. Image execution, the full graph connection, browser behavior and MetaMap compatibility remain separate milestones.

Formatting generated code must preserve owned module bytes. Generated module declarations carry rustfmt::skip so formatting the generated registration cannot rewrite the handler after its digest was captured. The staging helper rechecks every bound input after generation and refuses any change. Normal source formatting is an independent authoring check; the annotation grants no compilation, wire or admission exemption.
